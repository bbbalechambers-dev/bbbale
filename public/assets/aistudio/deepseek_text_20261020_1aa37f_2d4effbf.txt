5. CROSS-DEVICE DATA SYNC
================================================================================

5.1 CORE SYNC ARCHITECTURE

| Component        | Implementation                                  |
|------------------|-------------------------------------------------|
| Real-time        | Firestore onSnapshot on all active collections  |
| Fallback polling | Every 30 seconds if listener fails 3 times      |
| Foreground resume| On visibilitychange, re-fetch and re-subscribe  |
| Reconnection     | Exponential backoff: 1s, 2s, 4s, 8s, 16s, 30s  |
| Stale detection  | Cache older than 2 min -> "Syncing..." + refresh|
| Quota monitoring | Track daily reads/writes; alert if >80% of free |
| UI indicator     | Green Synced / Yellow Syncing / Red Offline /   |
|                  | Warning Reconnecting                            |

5.2 FIRESTORE LISTENER PATTERN (REQUIRED)

// Must use onSnapshot, not getDocs, for real-time
import { collection, onSnapshot, query, where } from "firebase/firestore";
import { db } from "./firebase";

function subscribeToCollection(collectionName, filters, callback) {
  const q = query(collection(db, collectionName), ...filters);
  const unsubscribe = onSnapshot(
    q,
    (snapshot) => {
      const data = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));
      callback(data);
    },
    (error) => {
      console.error("Listener error:", error);
      startPolling(collectionName, filters, callback);
    }
  );
  return unsubscribe;
}

function startPolling(collectionName, filters, callback) {
  const interval = setInterval(async () => {
    const q = query(collection(db, collectionName), ...filters);
    const snapshot = await getDocs(q);
    const data = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));
    callback(data);
  }, 30000);
  return () => clearInterval(interval);
}

document.addEventListener("visibilitychange", () => {
  if (document.visibilityState === "visible") {
    refreshAllListeners();
  }
});

|------------------------|-----------------|

5.4 NON-NEGOTIABLE SYNC RULES

1. Every record stored in Firestore - no device holds authoritative copy.
2. Every sync respects branch isolation (branch_id filtering).
3. Every sync respects role permissions (Firestore Security Rules).
4. Every conflict detected and resolved (last-write-wins with audit trail).
5. Listener must auto-reconnect on failure (exponential backoff).
6. Foreground resume must re-sync (visibilitychange event).
7. Quota monitoring must alert before limit (80% threshold).
8. Every sync survives Nigerian network conditions (polling fallback, retry).
